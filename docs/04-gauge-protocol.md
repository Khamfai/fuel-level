# 04 โปรโตคอลของ Veeder-Root TLS-350

อ้างอิงเอกสาร `vr350-3.pdf` (Serial Interface Manual) โค้ดอยู่ที่ `tls/protocol.py`

## การตั้งค่า serial

9600 baud, 8 data bits, no parity, 1 stop bit (8N1) เปลี่ยนได้ด้วย `--baud` ถ้า gauge ตั้งไว้ต่างจากนี้

## รูปแบบคำสั่ง

```
<SOH> i 201 TT
 01   │  │   └─ หมายเลขถัง 2 หลัก, 00 = ทุกถัง
      │  └───── function code
      └──────── ตัวพิมพ์เล็ก i = computer format (ตัวเลข), พิมพ์ใหญ่ I = display format (ข้อความอ่านง่าย)
```

`<SOH>` คือ byte `0x01` **ไม่ใช่** ข้อความ `<SOH>` ส่งเป็น `b"\x01i20100"`

## รูปแบบคำตอบ

```
<SOH> i201 TT YYMMDDHHmm <ข้อมูลแต่ละถัง...> && CCCC <ETX>
 01                                             03
```

- `YYMMDDHHmm` เวลาของ gauge (ในเอกสารบางฉบับระบุว่า unused ถ้าเป็น 0 ทั้งหมดโปรแกรมจะให้เป็น `null`)
- `&&` จุดสิ้นสุดข้อมูล
- `CCCC` checksum 4 ตัว hex
- `<ETX>` byte `0x03` โปรแกรมอ่านจนเจอ byte นี้ (ไม่ใช่อ่านทีละบรรทัด เพราะคำตอบไม่มี newline)

ถ้า gauge ไม่รู้จักคำสั่ง จะตอบ `<SOH>9999FF1B<ETX>`

## Checksum

ผลรวมของทุก byte ตั้งแต่ `<SOH>` ถึง `&&` บวกกับค่า `CCCC` ต้องหาร 65536 ลงตัว
(`(sum + CCCC) & 0xFFFF == 0`) ถ้าไม่ตรง โปรแกรมจะ error `checksum mismatch`
ปิดการตรวจได้ด้วย `--no-verify-checksum`

## ตัวเลขทศนิยม

ทุกค่าตัวเลขส่งมาเป็น IEEE-754 single precision เขียนเป็น hex 8 ตัว เช่น `447A0000` = 1000.0
โปรแกรมปัดเป็น 3 ตำแหน่งตอนส่ง API เพราะ single precision มีความละเอียดแค่ประมาณ 7 หลัก

หน่วยเป็นไปตามที่ตั้งใน gauge (แกลลอน/นิ้ว/°F หรือ ลิตร/มม./°C) โปรแกรมไม่แปลงหน่วย

## 201 In-Tank Inventory Report (`inventory`)

ข้อมูลแต่ละถัง: `TT` + `00000` (unused) + `NN` (จำนวน field, hex) + field ละ 8 hex

| ลำดับ | field ใน JSON | ความหมาย |
|---|---|---|
| 1 | `volume` | ปริมาตรรวมในถัง (น้ำมัน + น้ำ) |
| 2 | `tc_volume` | ปริมาตรชดเชยอุณหภูมิ (บาง gauge ส่ง 0) |
| 3 | `ullage` | ที่ว่างที่เติมได้อีก |
| 4 | `height` | ระดับน้ำมัน |
| 5 | `water` | ระดับน้ำที่ก้นถัง |
| 6 | `temperature` | อุณหภูมิ |
| 7 | `water_volume` | ปริมาตรน้ำ |

field ที่ 8 เป็นต้นไป (ถ้ามี) โปรแกรมอ่านข้ามไป

## 205 In-Tank Status Report (`status`)

ข้อมูลแต่ละถัง: `TT` + `nn` (จำนวน alarm, hex) + `AA` × nn (รหัส alarm 2 หลัก)

รหัส alarm ที่พบบ่อย (ครบทั้งหมดอยู่ใน `ALARM_NAMES` ใน `tls/protocol.py`):

| รหัส | ความหมาย |
|---|---|
| 02 | Tank Leak Alarm (น้ำมันรั่ว) |
| 03 | Tank High Water Alarm (น้ำในถังสูง) |
| 04 | Tank Overfill Alarm (เติมเกิน) |
| 05 | Tank Low Product Alarm (น้ำมันใกล้หมด) |
| 09 | Tank Probe Out Alarm (probe หลุด/เสีย) |
| 11 | Tank Delivery Needed Warning (ควรสั่งน้ำมัน) |

**พฤติกรรมของ gauge จริง**: ถังที่ไม่มี alarm gauge ส่ง `nn=00` แต่ยังตามด้วยรหัส alarm เปล่า `00`
หนึ่งตัว (เหมือนกรณี 20C) เช่น `01 00 00 | 02 00 00 | 03 00 00` โปรแกรมข้าม `00` นั้นให้
frame จริงอยู่ใน `tests/test_protocol.py`

**เผื่อไว้**: 205 อาจไม่มี field เวลา `YYMMDDHHmm` (ส่ง `TTnn...` ต่อจากหมายเลขถังทันที)
โปรแกรมลองแบบตามเอกสารก่อน ถ้า parse ไม่ผ่านจะลองแบบไม่มีเวลา ในกรณีนั้น `timestamp` เป็น `null`

**หมายเหตุ**: gauge จริงที่ทดสอบตอบ 205 ไม่สม่ำเสมอ (บางครั้งไม่ตอบ บางครั้งตอบไม่ครบ)
พบว่าเกิดเมื่อส่งคำสั่งทันทีหลังได้คำตอบก่อนหน้า โปรแกรมจึงเว้น 0.5 วินาทีระหว่างคำสั่ง
และส่งซ้ำอีกหนึ่งครั้งถ้าไม่ได้คำตอบใน 10 วินาที ถ้ายัง parse ไม่ผ่าน โปรแกรมจะข้ามรายงานนี้
และส่ง `inventory` ตามปกติ

## 20C In-Tank Most Recent Delivery Report (`delivery`)

ข้อมูลแต่ละถัง: `TT` + `p` (รหัสสินค้า 1 ตัว) + `dd` (จำนวนรอบเติม, decimal)
แต่ละรอบเติม: `YYMMDDHHmm` เริ่ม + `YYMMDDHHmm` จบ + `NN` + field × NN

| ลำดับ | field ใน JSON | ความหมาย |
|---|---|---|
| 1 | `start_volume` | ปริมาตรก่อนเติม |
| 2 | `start_tc_volume` | ปริมาตรชดเชยอุณหภูมิก่อนเติม |
| 3 | `start_water` | ระดับน้ำก่อนเติม |
| 4 | `start_temp` | อุณหภูมิก่อนเติม |
| 5 | `end_volume` | ปริมาตรหลังเติม |
| 6 | `end_tc_volume` | ปริมาตรชดเชยอุณหภูมิหลังเติม |
| 7 | `end_water` | ระดับน้ำหลังเติม |
| 8 | `end_temp` | อุณหภูมิหลังเติม |
| 9 | `start_height` | ระดับน้ำมันก่อนเติม |
| 10 | `end_height` | ระดับน้ำมันหลังเติม |
| คำนวณ | `amount` | `end_volume - start_volume` ปริมาณที่เติมเข้ามา |

ใช้เทียบกับใบส่งของว่าได้รับน้ำมันครบหรือไม่

**พฤติกรรมของ gauge จริง**: ถังที่ไม่มีประวัติการเติม gauge ส่ง `dd=00` แต่ยังตามด้วย record เปล่า
หนึ่งชุด (วันที่ `-001010800` ค่าเป็น 0 ทั้งหมด) ซึ่งต่างจากเอกสาร โปรแกรมตรวจจับและข้าม record นี้ให้
ผลลัพธ์คือ `deliveries: []` ตัวอย่าง frame จริงอยู่ใน `tests/test_protocol.py` (`REAL_20C_FRAME`)
